# kernel/

`photolib-kernel`: the small, pure Rust crate that holds every deterministic rule the server, the app, the CLI and
the viewer must agree on, so each rule is written once.

## Architecture

* **Pure by construction**: `#![forbid(unsafe_code)]`, and `clippy.toml` with denied lints rejects std I/O, threads,
  clocks, the environment and processes; `tests/lints.rs` proves both by linting a copy with a violation.
* **Bytes in, bytes out**: `call(method_id, request) -> CallResponse` and, for chunked crypto, `Stream::open/push/
  finish`; the messages are `proto/photolib/kernel/v1` (`Method` lists the ids), generated into `src/gen`.
* **Keys stay inside**: a `Keyring` holds keys and seeds by handle, zeroized on drop; callers supply all randomness.
  Besides `DatabaseKey`'s page key (ADR-0057), no response holds one (`no_response_holds_key_material`), but OPAQUE's
  session and export keys; nothing exports LinkSecret or LinkAuth until M6-09 (both confirmed in photolib-design#341).
* Scope: crypto and envelope formats, metadata, capture times, file names and grouping, ThumbHash encoding, query
  parsing, sync merge rules, image models' input, vector scan, map clustering, editing (`develop.rs`, `edit.rs`, `recipe*.rs`).
* Linked natively by the server and CLI, by native apps via the C ABI in `ffi/` (the only unsafe code shipped), as WASM.
* `testvectors/`: conformance vectors that Rust, Dart (all six targets) and TypeScript run; a difference is a bug.

## Contents

* `src/`: `call`, `Keyring` and `Stream` (`lib.rs`); [crypto v1](../docs/dev/crypto-v1.md): keys, HKDF, Argon2id, PLW
  wraps, dedup tokens and link keys (`keys.rs`), PLB (`blob.rs`), the lockbox and sealed journal entries (`local.rs`),
  public keys and PLH wraps (`share.rs`), PLS signing, identity and membership logs, upload statements and safety codes
  (`logs.rs`), OPAQUE for client and server (`opaque.rs`); `ReadMetadata` (`metadata.rs`, `metadata/`), EXIF, XMP and
  IPTC IIM over host-supplied byte ranges, merged by MWG 2.0 ([ADR-0036](../docs/adr/0036-kernel-metadata-reader.md)),
  and movies (`movie.rs` for ISOBMFF and QuickTime, AVI in `containers.rs`) with motion photos' videos (`motion.rs`);
  `PairLivePhotos` (`live_photo.rs`, [ADR-0044](../docs/adr/0044-kernel-movies-motion-and-live-photos.md)); `query.rs`;
  `ResolveCaptureTime` over a head or ranges (`capture_time.rs`, [ADR-0051](../docs/adr/0051-capture-time-resolver.md)).
* `tests/corpus.rs` compares `ReadMetadata` with the golden records of `testdata/corpus/` field by field (at least 99%
  must match), motion photos' videos, Live Photo pairs, panoramas and HDR exactly, and `ResolveCaptureTime` with their
  capture times (all but `UNMATCHED`); `tests/fuzz.rs` runs every corpus file, vector input and crypto request, damaged,
  and every find in `testdata/fuzz` through the targets of `fuzz/` (libFuzzer, outside the workspace; `bash
  tools/kernel/fuzz.sh` runs them beside the gate), failing on a panic, damaged authenticated input that passes and a
  file the reader holds many times over (`FUZZ_ROUNDS`, `FUZZ_SEED` run it longer).
* `ffi/`: `photolib-kernel-ffi`, the C ABI (`photolib_kernel_call`, `_stream_open/push/finish`, `_free`, and
  `_keyring_new/call/stream_open/free`), each failing a call that panicked with kernel.panic (`PANIC_PROBE`).
* `wasm/`: safe, single-threaded `photolib-kernel-wasm`; pages are not cross-origin isolated. wasm-bindgen exports
  `call`, `openStream`, `newKeyring`, `Keyring` and `Stream`; the `dart:js_interop` binding at
  `app/packages/photolib_kernel/lib/photolib_kernel_web.dart` has the same API as FFI; `wasm/guard.js` catches traps.
  `bash tools/kernel/wasm.sh <dir>` builds a SIMD ES module: `photolib_kernel_wasm.js`, `.wasm` and TypeScript types,
  loaded lazily by Flutter web and viewer. `tools/kernel/budget.mjs` rejects it over 1 MB brotli.
* `testvectors/*.json`: `{name, method, request, response}` (base64 protobuf); each case runs on a fresh keyring after
  its `setup` calls. Streams list pieces (base64, `{"pattern": n}` or `blobs` ranges) and per-step responses or `responses_sha256`.
  `tests/vectors.rs` generates and runs these typed cases (`BLESS=1 cargo test --test vectors` rewrites them).
  `app/packages/photolib_kernel` runs them over the C ABI (`flutter test`) and Chrome WASM (`bash tools/check.sh web`).
* `testvectors/crypto/`: known-answer vectors in the crypto v1 spec's schema, generated by
  `tools/cryptoref/vectors.py`; never hand-edit. `tests/vectors/crypto.rs` and `tests/vectors/sharing.rs` (PLH, PLS,
  OPAQUE) turn every file into calls in `testvectors/crypto.json`; a file not run fails the test.
* Native builds: `tools/kernel/build.py` cross-compiles `ffi/` for Android, iOS, macOS, Windows and Linux; apps bundle
  those prebuilt libraries, checksum-verified, without Rust ([ADR-0026](../docs/adr/0026-kernel-prebuilt-libraries.md)).
* Budgets: `build.py` fails a library over 3 MB and `app/packages/photolib_kernel/test/bench.dart` a binding below
  ADR-0004's speed thresholds, PLB decrypt below 1 GiB/s natively or 300 MiB/s in WASM, or Argon2id at the device
  floor over 600 ms; the numbers per target are in the [go/no-go report](../docs/dev/kernel-go-no-go.md). Stream large
  input in 64 KiB pieces: natively, larger buffers cost page faults on every step. Seeks decrypt a chunk run (ADR-0059).

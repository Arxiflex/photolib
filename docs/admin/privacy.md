# Outbound connections (privacy manifest)

Photolib does not phone home: no telemetry, no crash reports, and no update checks unless you turn them on. The apps
connect only to the servers you add, and photolibd only to the services you configure, such as PostgreSQL, object
stores and OpenID Connect providers. Every other connection is listed here with a self-hosted alternative. A
connection missing from this page is a bug: report it in an issue.

The gate checks this page (`tools/tests/check_outbound.py`): it fails when a URL in product code names a host, or a
periodic timer starts, that no row lists (the kernel's own code is skipped: its lints forbid sockets and clocks), or
when a run-time path or a task on a timer lacks a kill switch, a timeout or a far-future-date test; review covers what
a scan cannot see. That test runs the path with the clock in 2100: it keeps working, or stops without deleting
anything or locking anyone out. The gate runs `cargo test`, `flutter test` and `npm test` with egress blocked
(`tools/offline.sh`), so they cannot depend on the internet.

## At run time

Only the model download, webhooks and the public-URL self-test exist yet: each other row is what the roadmap item that
builds it must ship. Every connection is off by default: photolibd's first-run setup, and the apps on first use, ask
once per connection, naming the host it contacts. Connected apps get maps, models and places from their server. For
air-gapped installs, `outbound: none` in photolibd's configuration (`PHOTOLIB_OUTBOUND=none`) turns every connection
here off and wins over each one's switch.

## On a timer

These contact nothing beyond the services you configure, but run on their own and fail safe the same way.

| Task | When | Kill switch | Timeout | Far-future test | Code |
|---|---|---|---|---|---|
